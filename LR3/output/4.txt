ПРИМЕР 1: Демонстрация проблемы Race Condition
================================================================================
Проблема: несколько потоков изменяют общий ресурс без синхронизации

Запуск 10 потоков, каждый увеличивает счетчик 1000 раз
Ожидаемый результат: 10000
Фактический результат: 10000
❌ Результат НЕВЕРНЫЙ из-за race condition!
   Потоки одновременно изменяли счетчик без синхронизации

================================================================================
ПРИМЕР 2: Решение проблемы через synchronized
================================================================================
Решение: использование synchronized для защиты критической секции

Запуск 10 потоков, каждый увеличивает счетчик 1000 раз
Ожидаемый результат: 10000
Фактический результат: 10000
✓ Результат ВЕРНЫЙ благодаря synchronized!
  Синхронизация гарантирует, что только один поток изменяет счетчик
